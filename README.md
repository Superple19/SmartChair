# SmartChair

## 전동휠체어 오조작 및 사고 방지 제동 시스템

Arduino Mega 2560 기반의 생체 신호·거리 센서 융합형 스마트 휠체어 안전 제어 시스템이다.

심박 센서에서 탑승자의 상태를 판단하고, 좌·우 TF-Luna 라이다에서 계산한 접근 상태 정보를 결합하여 양측 브레이크 서보를 제어한다.

## 사용 부품

| 부품 | 모델·수량 | 용도 및 연결 |
|---|---|---|
| 제어보드 | Arduino Mega 2560 ×1 | 전체 센서 입력 및 제동 제어 |
| 심박 센서 | DFRobot SEN0203 ×1 | 디지털 모드 심박 펄스 입력, D5 |
| 거리 센서 | Benewake TF-Luna ×2 | 좌측 `Serial1`, 우측 `Serial2`로 거리·속도 측정 |
| 브레이크 서보모터 | FT5330M ×2 | 좌측 D2, 우측 D3 신호 제어, 6V 납축전지 별도 전원 |
| 서보 전원 배선 | 6V 납축전지, 18AWG | 두 서보의 전원 공급용 별도 전원선 |
| 테스트 버튼 | 일반 순간 푸시 버튼 ×1 | 무맥박 상태 테스트, D4 `INPUT_PULLUP` |

## 안전 설계 관점

ISO 26262의 기능 안전 개념을 참고하여 센서 검증, 안전 대응 제어 및 안전 상태 전환 구조를 설계한다. [ISO 26262 공식 범위](https://www.iso.org/standard/68390.html)

여기서 안전 대응 제어는 무효 입력 제외, 지속 프레임 확인, 무맥박 상태 래치와 같은 제어 로직을 의미하며, ISO 26262 적합성·인증·ASIL 충족을 주장하지 않는다.

## 하드웨어 핀 배치

| 장치 | 연결 |
|---|---|
| 좌측 브레이크 서보 | D2 |
| 우측 브레이크 서보 | D3 |
| 무맥박 상태 테스트 버튼 | D4, `INPUT_PULLUP` |
| 디지털 심박 센서 | D5 |
| 좌측 TF-Luna | `Serial1` |
| 우측 TF-Luna | `Serial2` |

### 배선 및 센서 설정

- **SEN0203**: 보드의 출력 선택 스위치를 **Digital**로 설정한다. 센서 신호선을 D5에 연결하며, 현재 코드는 디지털 사각파 펄스의 상승 엣지를 기준으로 IBI를 측정한다. 전원은 5V를 사용하고 GND는 Arduino Mega와 공통으로 연결한다.
- **좌측 TF-Luna**: 센서 TX를 Mega의 `Serial1` 수신 핀 RX1(D19)에 연결한다. 현재 수신 전용으로 사용하므로 Mega의 TX1(D18)과 센서 RX는 연결하지 않는다. 센서는 정격 범위 내의 5V 전원과 공통 GND를 사용한다.
- **우측 TF-Luna**: 센서 TX를 Mega의 `Serial2` 수신 핀 RX2(D17)에 연결한다. 현재 수신 전용으로 사용하므로 Mega의 TX2(D16)와 센서 RX는 연결하지 않는다. 센서는 정격 범위 내의 5V 전원과 공통 GND를 사용한다.
- **FT5330M**: 좌측 신호선은 D2, 우측 신호선은 D3에 연결한다. 두 서보의 전원은 Arduino Mega에서 공급하지 않고 6V 납축전지에서 별도로 공급한다. 전원 배선은 18AWG를 사용하며, 서보 전원의 GND와 Arduino Mega의 GND는 PWM 신호 기준을 위해 공통으로 연결한다.
- **테스트 버튼**: 버튼을 D4와 GND 사이에 연결한다. 내부 풀업을 사용하므로 눌림 상태는 `LOW`로 읽힌다.

## 전원 구성

- **MCU 전원부**: Arduino Mega 2560은 9V 사각전지와 배터리 스냅 DC 플러그를 사용해 별도로 공급한다.
- **서보 전원부**: FT5330M 서보 2개는 6V 납축전지를 사용하며, 서보 전원은 Arduino Mega의 5V 핀에서 공급하지 않는다.
- MCU 전원과 서보 전원을 분리하여 서보 구동 시 전압 강하, 보드 리셋, 센서 노이즈 발생을 줄인다.
- 전원을 분리하더라도 PWM 신호 기준을 맞추기 위해 Arduino Mega GND와 서보 전원부 GND는 반드시 공통으로 연결한다.
- 서보 전원 배선은 18AWG를 사용한다.

|---|---:|---|

| `NO_PULSE_BRAKING_TIME` | 2000ms | 무맥박 상태 대응 시 제동각을 180°에서 0°로 변경하는 시간 |

## 1. 심박 신호 처리

### 1.1 IBI 범위 검증

심박 센서의 상승 엣지 사이 시간을 IBI(Inter-Beat Interval)로 계산한다.

```text
IBI = currentTime - lastBeatTime
```

생리학적으로 허용하는 입력 범위는 다음과 같다.

- `IBI <= 300ms`: 200BPM 이상으로 간주하고 비정상 입력 처리
- `IBI >= 2000ms`: 30BPM 이하로 간주하고 비정상 입력 처리
- 유효 범위: `300ms < IBI < 2000ms`

유효한 IBI는 BPM으로 변환한다.

```text
BPM = 60000 / IBI
```

### 1.2 비정상 펄스 카운터

IBI 범위를 벗어난 펄스가 발생할 때마다 `invalidPulseCount`를 증가시킨다.

- 유효한 펄스가 들어오면 카운터를 0으로 초기화한다.
- 비정상 펄스가 8회 연속 발생하면 센서 접촉이 해제된 상태로 판정한다.
- 센서 접촉 해제 상태에서는 신호 이상을 무맥박 상태로 오인하지 않고 주행 제어를 유지한다.

### 1.3 다수결 기반 센서 접촉 상태 판정

유효한 BPM을 5개 링 버퍼에 저장하고, 최근 5개 중 140BPM 이상의 값이 4개 이상이면 센서 접촉 해제 상태로 판정한다.

```text
highNoiseCount >= 4 && NUM_BPM_READINGS == 5
```

긴장이나 일시적인 빈맥은 단일 값으로 판단하지 않고, 반복적으로 고 BPM 신호가 입력되는 경우에만 센서 접촉 해제 상태로 전환한다.

### 1.4 절사 평균 필터

5개의 BPM을 오름차순으로 정렬한 뒤 최댓값과 최솟값을 제거하고 중앙 3개의 평균을 최종 BPM으로 사용한다.

```text
sortedBpm[1..3]의 평균 = averageBPM
```

이 방식은 순간적인 BPM 스파이크가 전체 평균을 크게 왜곡하는 것을 완화한다.

## 2. 무맥박 상태 감지 및 안전 대응 제어

무맥박 상태 판정은 심박 샘플이 충분히 준비되고 센서 접촉 상태가 확인된 경우에 수행한다.

다음 조건 중 하나라도 충족되면 무맥박 상태 대응으로 전환한다.

1. `averageBPM < 40`
2. 마지막 펄스 엣지 이후 경과 시간이 `NO_PULSE_TIMEOUT`(2000ms)을 초과
3. 무맥박 상태 테스트 버튼 입력

무맥박 상태 대응이 시작되면 `responseStartTime`을 기록하고, 해당 상태를 유지한 채 제동 제어로 전달한다.

무맥박 상태 대응은 자동으로 해제하지 않고 안전 래치로 유지한다. 시스템 재시작 또는 리셋 후 센서 초기 상태로 돌아가도록 하여, 일시적인 신호 회복만으로 제동이 해제되는 것을 방지한다. 이 상태는 의료적 진단이 아니라 센서 입력에 따른 제어 상태다.

## 3. 라이다 데이터 처리

좌·우 TF-Luna는 `Serial1`, `Serial2`에서 115200bps로 수신한다. 각 센서의 9바이트 패킷에서 거리와 반사 신호 강도를 추출한다.

### 3.1 1차 유효성 검증

다음 조건을 모두 만족하는 데이터만 유효한 거리로 사용한다.

- 반사 신호 강도 `>= 1500`
- 거리 `> 0cm`
- 거리 `< 800cm`

조건을 만족하지 않으면 해당 센서의 거리값을 800cm, 신호 강도를 0으로 처리하여 제동 대상에서 제외한다.

현재 구현은 패킷 헤더, 거리 범위, 반사 신호 강도, 프레임 지속 조건을 중심으로 입력을 검증한다. TF-Luna 체크섬 검증과 통신 신선도 타임아웃은 현재 시제품 구현 범위에 포함하지 않는다.

유효하지 않은 입력은 오인식에 따른 불필요한 제동을 줄이기 위해 접근 제동 계산에서 제외한다. 이 동작은 시제품의 입력 처리 정책이며, 고장 진단을 포함한 안전 인증 수준의 Fail-Safe 동작을 의미하지 않는다.

### 3.2 상대 접근 속도

100ms 간격으로 이전 거리와 현재 거리의 변화를 계산한다.

```text
V_rel = (previousDistance - currentDistance) / dt
```

양수이면 장애물이 접근 중이고, 0 이하이면 접근 상태가 아닌 것으로 처리한다.

### 3.3 TTC(Time-To-Collision)

접근 속도가 양수이고 현재 거리가 400cm 미만인 경우 TTC를 계산한다.

```text
TTC = currentDistance / V_rel
```

그 외의 경우 TTC는 99초로 설정하여 안전 상태로 표시한다.

### 3.4 센서 배치 범위

TF-Luna는 단일 지점을 측정하는 1D 거리 센서이므로, 좌·우에 각각 배치하여 전방 양측 영역을 분할 관측한다. 두 센서의 배치로 2D 라이다와 유사한 양측 감지 범위를 구성하지만, 센서 사이와 측면에는 관측 사각이 생길 수 있어 장착 각도와 위치 정렬이 중요하다.

### 3.5 제동거리

물리적으로 필요한 제동거리는 상대속도와 최대 감속도 15cm/s²를 사용해 계산한다.

```text
requiredBrakingDistance = V_rel² / (2 × MAX_DECELERATION)
approachBoundary = requiredBrakingDistance + SAFETY_MARGIN
```

계산된 물리 제동거리에 150cm의 안전마진을 한 번 추가하여 접근 경계를 정하고, 이 경계를 기준으로 비례 제동을 시작한다.

## 4. 라이다 노이즈 및 제동각 필터

- 상대속도 `<= 30cm/s`: 정지 또는 저속 상태로 간주하고 제동 개입을 하지 않는다.
- 상대속도 절댓값 `>= 1000cm/s`: 순간적인 속도 스파이크로 간주하고 속도를 0으로 제거한다.
- 유효하지 않은 거리·신호 강도: 제동 해제각 180°를 출력한다.

## 5. 제동각 산출

제동각은 우측 기준으로 `180°=제동 해제`, `0°=최대 제동`이다.

### 즉시 제동

다음 조건 중 하나라도 충족하면 즉시 목표 제동각 0°를 산출한다.

- 장애물 거리 `<= 120cm`
- TTC `<= 1.0초`

### 비례 제동

즉시 제동 조건에는 도달하지 않았지만 현재 거리가 접근 경계 안쪽이면 제동각을 선형으로 계산한다.

3.5절에서 계산한 `approachBoundary`(물리 제동거리와 안전마진의 합)를 기준으로 비례 제동을 적용한다.

접근 경계와 120cm 사이의 거리를 140°~20° 범위로 매핑한다. 장애물에 가까워질수록 제동각이 작아져 제동력이 증가한다.

### 안전 상태

장애물이 없거나 저속 상태이고 접근 조건이 충족되지 않으면 목표 제동각 180°를 출력하여 제동을 해제한다.

## 6. 자동 제동 유지

제동 명령은 100ms 주기로 검증한다.

1. 접근 신호가 3회 연속 감지되면 약 0.3초 후 제동을 시작한다.
2. 비례 제동 신호가 8회 연속 감지되면 약 0.8초 지속 상태로 판정한다.
3. 즉시 제동 신호가 10회 연속 감지되면 약 1.0초 지속 상태로 판정한다.
4. 지속 상태로 판정된 뒤 장애물 신호가 해제되어도 최소 1초간 제동을 유지한다.

단순한 일시적 거리 변동으로 제동이 반복적으로 해제되는 것을 막고, 접근 신호가 지속될 때만 자동 제동 유지를 활성화한다.

## 7. 무맥박 상태 대응 제동

무맥박 상태가 감지되면 제동 목표각을 2000ms 동안 선형으로 변경한다.

```text
180° → 0°
```

좌측 서보는 우측 목표각의 반대 방향으로 동작한다. 우측은 좌우 장력 차이를 보정하기 위해 제동 진행률의 98%를 적용한다.

```text
leftAngle = 180 - rightAngle
rightAngle = 180 - (leftBrakeProgress × 0.98)
```

무맥박 상태 대응 제동은 일반 라이다 제동보다 우선하며, 해당 상태에서는 탑승자 보호를 위해 제동 상태를 유지한다.

## 8. 실행 흐름

```text
센서 입력
  ├─ HeartSensor: IBI/BPM/무맥박 상태 대응
  ├─ Left Lidar: 거리/속도/TTC/제동각
  └─ Right Lidar: 거리/속도/TTC/제동각
          ↓
BrakeController: 접근 신호 융합·프레임 검증·자동 제동 유지
          ↓
ServoBrake: 좌·우 보정 각도 출력
```
